# Transfer resume safety

Resume is not a general guarantee that a file is a stable snapshot. Use a trusted local destination directory and avoid modifying the partial, destination, or remote source during a transfer.

- The GUI's verified download resume copies a checkpoint into a private stage, checks its prefix and publishes without overwriting a destination. WebDAV and S3 require a strong ETag and a server that honors conditional requests; versioned S3 also requires version confirmation.
- FTP and SFTP cannot pin an atomic source snapshot. Resume is refused by default and is offered only with explicit per-transfer best-effort approval. Concurrent changes to remote or local files can still corrupt the result, even when size and modification time match. Start a fresh transfer instead if that risk is unacceptable.
- The legacy ordinary engine download path keeps the verified partial's open descriptor for subsequent writes, and on Unix checks its identity against the pathname before publication. It still publishes by pathname, so the check and publication are not atomic, and concurrent writers can modify the open file. This path does not have the GUI verified-resume path's private-copy protection; do not use it with untrusted local writers. Adopting a destination into a stage can fail on platforms that prohibit renaming an open file; retry with a fresh transfer. Closing that race requires safe ownership and publication semantics across platforms, not just a size or timestamp check.
- Guarded FTP and SFTP uploads use fresh stages and refuse resume rather than adopting an untrusted remote partial. The GUI currently refuses upload resume for all protocols. Retry a fresh upload; do not assume a remote partial is safe to reuse. Conditional WebDAV/S3 capabilities do not imply GUI upload-resume support.
- Resume with ASCII conversion is refused: byte offsets in converted text do not reliably correspond to source offsets. Select binary mode or restart without resume. Direct ordinary downloads also refuse existing complete, oversized, or unsafe destination files instead of silently overwriting them.
- Android Storage Access Framework granted-folder session transfers do not support verified resume. Restart as a fresh transfer; the provider bridge does not supply the required safe partial-file semantics.

Provider behavior, third-party server interoperability, physical Android devices, and the legacy pathname race remain open validation or development work. These limitations are not evidence of atomic snapshot support.
